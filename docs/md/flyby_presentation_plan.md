# 플라이바이 발표 구상 및 제작 계획

- 작성일: 2026-10-19
- 프로젝트 기준 위치: `docs/md/flyby_presentation_plan.md`
- 기준 대화: [플라이바이 이론 설명](chatgpt-conversation://6ad11aa3-8e58-83e8-a765-dfb2a5e90a81)
- 문서 목적: 대화에서 정리한 발표 방향과 20장 구성을 하나의 제작 기준으로 보관함
- 제작 형태: 발표자가 설명하는 HTML 발표 자료를 기준으로 함. 아래의 `PPT 문구`는 실제 화면에 표시할 문구를 의미함
- 현재 단계: 구상 정리 및 제작 준비 단계임. HTML·PPT 파일 제작은 포함하지 않음

## 1. 확정 범위와 문서 사용법

### 대화에서 정리된 방향

- 지문 설명을 발표의 중심으로 둠
- 플라이바이 추가 조사는 지문 이해를 돕는 정도로 제한함
- 탐사선이 문제를 해결해 가는 이야기로 구성함
- 한 장에 핵심 메시지 하나만 제시함
- 설명을 한 장에 몰아넣는 대신 여러 장으로 나눔
- `WHY?`, `FLYBY`, `ROSETTA`처럼 단어나 질문만 크게 보여주는 전환 장면을 활용함
- 화면의 글은 줄이고, 발표자의 설명과 애니메이션을 연결함
- 가속·감속·방향 전환, 움직이는 행성, 접근 조건, 반복 이용을 추가 조사에 포함함
- 실제 사례는 로제타를 중심으로 제한함
- 처음의 질문을 마지막 결론에서 회수함

### 확정된 방향과 구체화 제안의 구분

| 구분 | 내용 |
| --- | --- |
| 대화의 기준 구성 | 마지막으로 제시된 20장 순서와 각 장의 중심 메시지임 |
| 이 문서의 구체화 | 대화의 문구와 연출을 정돈하고, 장면 연결·발표용 대본·구현 주의사항을 보충함 |
| 제작 중 조정 가능 | 정확한 문장, 색상, 글꼴, 재생 길이, 세부 움직임, 최종 슬라이드 수임 |
| 아직 미확정 | 발표 제한 시간, 원 지문의 정확한 문장과 쪽수, 최종 디자인, 실제 발표 속도임 |

- 20장은 최종 장수 계약이 아니라 스토리보드 기준임
- 전체 내용은 약 9개 이야기 단위이며, 이를 20개 장면으로 나눈 구성임
- 제작 후 비슷한 장면을 합치거나 긴 설명을 나눌 수 있음
- 아래 `말할 내용`은 발표용 정리안임. 사용자가 모든 문장을 최종 확정했다는 의미는 아님
- 원 지문은 이번 작업에 제공되지 않아 직접 대조하지 못함
- `중력 웅덩이`, `환승역`, 지문 속 로제타 사례는 이전 대화에서 지문 내용으로 언급된 항목임
- 지문을 직접 인용하거나 “지문에서는 이렇게 말합니다”라고 발표하기 전 원문을 대조해야 함
- 과학적 오해를 줄이기 위한 보충 설명은 제작 메모에 둠. 이를 모두 화면에 넣지 않음

## 2. 발표 목적과 중심 질문

### 발표 목적

- 지문에서 설명하는 중력과 탐사선의 이동을 쉽게 전달함
- 플라이바이가 필요한 이유를 이야기의 흐름으로 이해하게 함
- 중력이 이동을 방해하는 동시에 궤도 설계에 이용될 수 있음을 보여줌
- 로제타의 행성 경유를 통해 개념을 실제 사례와 연결함

### 중심 질문

> 더 먼 곳으로 가는데, 오히려 중간 지점에는 더 빨리 도착할 수 있을까?

### 마지막에 남길 문장

> 가장 짧은 길이 항상 가장 좋은 길은 아니다.

> 중력을 이겨내는 대신, 중력을 이용한다.

### 설명 수준

- “어떻게 계산하는가?”보다 “왜 이런 방법을 쓰는가?”에 집중함
- 에너지·운동량 교환은 에너지가 저절로 생기는 것이 아니라는 설명에 필요한 만큼만 사용함
- 좌표계는 `행성에서 볼 때`와 `태양에서 볼 때` 정도로만 구분함
- 복잡한 공식, 벡터 합성, 수치 계산은 본 발표에서 제외함
- 지문에 없는 내용을 장황하게 늘려 별도의 우주공학 강의로 만들지 않음

```text
  ↓
지구의 중력 때문에 많은 에너지가 필요함
  ↓
중력 웅덩이에서 빠져나가는 상황 이해
  ↓
계속 중력을 이겨내야 할까?
  ↓
다른 행성의 중력을 이용하자
  ↓
FLYBY: 속도와 방향을 바꾸는 방법
  ↓
가속·감속·방향 전환
  ↓
그런데 왜 더 빨라질까?
  ↓
정지한 행성: 접근할 때 빨라졌다가 멀어지며 느려짐
  ↓
실제 행성: 움직임을 이용하면 태양 기준 속력도 바꿀 수 있음
  ↓
그래서 돌아가는 경로도 유리할 수 있음
  ↓
단, 접근 방향·거리·타이밍을 설계해야 함
  ↓
ROSETTA: 지구와 화성의 중력을 여러 차례 이용
  ↓
행성을 우주의 환승역처럼 이용함
  ↓
가장 짧은 길이 항상 가장 좋은 길은 아니다
  ↓
FLYBY
```

## 4. 슬라이드별 스토리보드

### 01. 더 먼 곳으로 가는데, 더 빨리?

**핵심 메시지**

- 목적지가 더 멀어도 중간 지점까지 더 빨리 가는 임무가 있을 수 있음

**PPT 문구**

> 더 먼 곳으로 가는데  
> 더 빨리 갈 수 있다?

**애니메이션**

1. 어두운 우주 배경 위에 지구와 목성을 배치함
2. 탐사선 A는 목성을 목적지로 하는 경로를 보여줌
3. 탐사선 B는 목성을 통과해 더 먼 곳으로 향하는 경로를 보여줌
4. B가 먼저 목성 부근에 도착하는 비교 장면을 연출함
5. 이유를 밝히지 않은 채 두 경로를 남김

**말할 내용**

> 보통 더 먼 곳으로 가려면 더 오래 걸린다고 생각합니다. 그런데 목성에 머무는 임무보다, 목성을 지나 더 먼 곳으로 가는 임무가 목성 근처에는 더 빨리 도착하는 경우도 있습니다. 왜 이런 일이 가능할까요?

**다음 장 연결**

- 경로와 행성을 어둡게 처리하고 `WHY?`로 연결함

**제작 메모**

- 대화에서 정한 도입 질문을 유지함. 모든 임무에서 성립하는 규칙으로 설명하지 않음
- A는 목성 옆에서 완전히 정지시키지 않고 궤도에 머무는 모습으로 표현함
- 특정 임무명과 소요 시간은 원 지문이나 별도 근거를 확인하기 전 넣지 않음
- 이 비교는 임무 목표·발사 조건·도착 조건이 다를 수 있는 사례임
- 목성에서 이후에 받는 중력 도움이 목성 도착 이전의 시간을 줄였다고 설명하지 않음

### 02. WHY?

**핵심 메시지**

- 답을 바로 말하지 않고 질문을 충분히 인식하게 함

**PPT 문구**

> WHY?

**애니메이션**

1. 이전 장의 배경을 유지함
2. 행성과 궤적의 밝기를 낮춤
3. `WHY?`를 화면 중앙에 크게 등장시킴
4. 약한 확대 효과 후 멈춤

**말할 내용**

> 그 이유를 알아보려면 먼저 탐사선이 어떻게 지구를 떠나는지부터 생각해 봐야 합니다.

**다음 장 연결**

- 지구 쪽으로 시선을 옮기며 탐사선의 출발 장면으로 연결함

### 03. 그냥 목적지로 가면 안 될까?

**핵심 메시지**

- 가장 단순해 보이는 방법부터 시도함

**PPT 문구**

> 가장 간단한 방법  
> 지구 → 탐사선 → 목적지

- 마지막에 기존 문구를 약하게 처리하고 `그런데…`만 강조함

**애니메이션**

1. 지구 가까이 탐사선을 배치함
2. 목적지까지 단순한 안내선을 표시함
3. 엔진 불꽃과 함께 탐사선이 출발함
4. 불꽃이 커지고 에너지 소모를 암시하는 짧은 효과를 넣음
5. 지구 방향의 중력 표시가 등장할 준비를 함

**말할 내용**

> 우주에는 도로나 장애물이 없으니 목적지를 향해 바로 가면 가장 쉬울 것 같습니다. 하지만 지구를 떠나는 것부터 쉽지 않습니다.

**다음 장 연결**

- 같은 탐사선과 지구를 유지하고 중력 화살표를 추가함

**제작 메모**

- 직선은 처음 떠올리는 생각을 보여주는 개념도임. 실제 행성 간 비행 궤도라고 제시하지 않음
- 연료 게이지를 쓴다면 수치 없는 짧은 보조 표현으로 제한함

### 04. 문제는 중력

**핵심 메시지**

- 지구에서 벗어나려면 중력에 맞서 에너지를 공급해야 함

**PPT 문구**

> 지구가 놓아주지 않는다.

- 보조 단어는 `중력` 하나만 사용함

**애니메이션**

1. 탐사선이 지구에서 멀어지려는 장면을 이어감
2. 지구 중심을 향한 중력 화살표를 표시함
3. 엔진 분사를 강조해 탈출에 필요한 에너지를 표현함
4. 복잡한 수치나 힘의 분해 없이 화면을 정리함

**말할 내용**

> 지구는 탐사선을 계속 자신 쪽으로 잡아당깁니다. 그래서 지구의 중력을 벗어나려면 많은 에너지가 필요합니다.

**다음 장 연결**

- 중력의 영향을 웅덩이 비유로 바꾸어 보여줌

### 05. 중력 웅덩이

**핵심 메시지**

- 지구를 떠나는 데 필요한 에너지를 웅덩이에서 올라오는 모습으로 이해함

**PPT 문구**

> 중력 웅덩이

**애니메이션**

1. 지구 주변에 단순한 격자 또는 곡면을 등장시킴
2. 지구 주변이 움푹 들어간 형태로 변형됨
3. 탐사선을 낮은 위치에 표시함
4. 탐사선이 바깥으로 올라가려는 움직임을 보여줌

**말할 내용**

> 이것을 중력 웅덩이로 생각하면 이해하기 쉽습니다. 탐사선이 깊은 웅덩이 안에 있고, 그 밖으로 올라가야 하는 것과 비슷합니다. 밖으로 나가려면 에너지가 필요한 것입니다.

**다음 장 연결**

- 같은 웅덩이 장면을 멈추고 질문을 띄움

**제작 메모**

- 이전 대화에서 지문과 연결한 핵심 비유임. 지문 대조 후 원문의 표현으로 맞춤
- 에너지 관계를 설명하는 비유임을 제작자가 이해해야 함
- 실제 우주 공간에 아래로 떨어지는 구멍이 있다는 식으로 설명하지 않음
- 일반상대성이론의 정밀한 시공간 모형을 구현하는 작업으로 확대하지 않음

### 06. 그렇다면…

**핵심 메시지**

- 중력을 상대하는 관점을 바꾸도록 질문함

**PPT 문구**

> 계속 중력을  
> 이겨내야 할까?

**애니메이션**

1. 이전 장면의 움직임을 설명용 정지 화면으로 바꿈
2. 엔진 불꽃을 약하게 하거나 숨김
3. 배경을 어둡게 하고 질문을 크게 표시함
4. 발표자가 다음 말을 할 여유를 둠

**말할 내용**

> 그런데 생각을 조금 바꿔볼 수 있습니다. 중력을 계속 이겨내려고만 하지 말고, 이용할 수는 없을까요?

**다음 장 연결**

- 다른 행성 근처를 지나가는 장면으로 전환함

**제작 메모**

- 정지는 발표 연출임. 엔진을 끄면 실제 탐사선이 우주에서 멈춘다는 의미가 아님

### 07. 중력을 이용한다

**핵심 메시지**

- 다른 행성의 중력을 궤도를 바꾸는 데 이용할 수 있음

**PPT 문구**

> 중력을 이기는 대신  
> 이용한다.

**애니메이션**

1. 다른 행성과 접근 중인 탐사선을 보여줌
2. 탐사선이 행성 가까이 지나가며 경로가 부드럽게 휘어짐
3. 휘어진 궤적을 짧게 남김
4. 엔진 불꽃을 강조하지 않고 행성의 영향에 시선을 모음

**말할 내용**

> 탐사선이 다른 행성 가까이 지나가면 그 행성의 중력이 탐사선을 끌어당깁니다. 이 힘을 잘 이용하면 많은 연료를 쓰지 않고도 탐사선의 이동 방향을 바꿀 수 있습니다.

**다음 장 연결**

- 휘어진 궤적 위로 이 방법의 이름을 등장시킴

**제작 메모**

- 지구 탈출 자체가 생략되는 것으로 보이지 않도록 장면을 분리함
- 행성 표면과 충돌하거나 표면에서 튕기는 형태로 그리지 않음

### 08. FLYBY

**핵심 메시지**

- 방금 본 방법의 이름과 뜻을 짧게 연결함

**PPT 문구**

> FLYBY

- 처음에는 제목만 표시함
- 이어서 정의를 두 줄로 표시함

> 천체의 중력을 이용해  
> 탐사선의 속도와 방향을 바꾸는 방법

- 보조 표기: `Gravity Assist · 중력 도움`

**애니메이션**

1. 이전 장의 탐사선이 행성을 빠져나감
2. 궤적을 남기고 `FLYBY`가 등장함
3. 발표자의 설명에 맞춰 정의를 추가함

**말할 내용**

> 이런 행성 통과를 이용하는 방법이 중력 도움, Gravity Assist입니다. 이번 발표에서는 이 방법을 중심으로 플라이바이를 살펴보겠습니다. 천체의 중력을 이용해 탐사선의 속도와 방향을 바꾸는 것입니다.

**다음 장 연결**

- 정의의 `속도와 방향`을 다음 장의 세 가지 변화로 이어감

**제작 메모**

- 대화에서 사용한 간단한 정의를 유지하되, 이 발표에서 다루는 범위를 밝힘
- 엄밀히 flyby는 천체 가까이를 통과하는 비행을 뜻함. 모든 flyby가 중력 도움을 주목적으로 하는 것은 아님
- 용어 차이를 별도의 긴 설명 슬라이드로 늘리지는 않음

### 09. 플라이바이로 할 수 있는 것

**핵심 메시지**

- 속력을 높이는 것 외에도 감속과 방향 전환이 가능함

**PPT 문구**

> 가속  
> 감속  
> 방향 전환

**애니메이션**

1. 세 가지 변화를 차례로 강조함
2. 가속 장면은 통과 뒤 탐사선의 움직임이 빨라지는 것으로 표현함
3. 감속 장면은 통과 뒤 움직임이 느려지는 것으로 표현함
4. 방향 전환 장면은 휘어진 궤적에 시선을 모음
5. 세 장면을 모두 계속 움직이게 하기보다 설명 중인 장면만 재생함

**말할 내용**

> 플라이바이는 탐사선을 빠르게 만드는 데만 쓰이지 않습니다. 접근 방법에 따라 속력을 높일 수도, 낮출 수도 있고 진행 방향도 바꿀 수 있습니다.

**다음 장 연결**

- 가속 장면을 남기고 그 이유를 질문함

**제작 메모**

- 가속과 감속의 비교 기준은 이 장에서 태양 기준으로 통일함
- 세 항목은 완전히 독립된 효과가 아님. 속력과 방향이 함께 달라질 수 있음
- 수치 패널과 벡터 합성도는 넣지 않음

### 10. 그런데 왜 빨라질까?

**핵심 메시지**

- 중력에 끌려가는 것만으로 최종 속력 증가가 설명되는지 질문함

**PPT 문구**

> 그런데…  
> 왜 빨라질까?

**애니메이션**

1. 탐사선과 행성 외의 요소를 정리함
2. 궤적을 약하게 남김
3. 질문을 중앙에 크게 표시함

**말할 내용**

> 그런데 궁금한 점이 하나 생깁니다. 행성에 끌려갔다가 다시 멀어지는 것뿐인데, 어떻게 속력을 더 얻을 수 있을까요?

**다음 장 연결**

- 우선 행성이 고정된 단순한 경우를 보여줌

### 11. 행성이 멈춰 있다면?

**핵심 메시지**

- 행성 기준으로 보면 접근할 때 빨라졌다가 이탈할 때 다시 느려짐

**PPT 문구**

> 행성이 멈춰 있다면?  
> 빨라짐 → 다시 느려짐

- 재생이 끝날 때 기존 보조 문구를 다음 문장으로 교체함

> 처음 속력 ≈ 마지막 속력

**애니메이션**

1. 행성을 화면 중앙에 고정함
2. 탐사선이 가까워질수록 움직임이 빨라짐
3. 최근접점을 지나 멀어지며 다시 느려짐
4. 행성에서 충분히 먼 진입 지점과 이탈 지점을 강조함
5. 두 지점의 속력은 비슷하지만 방향이 달라졌음을 궤적으로 보여줌

**말할 내용**

> 행성에서 바라본다고 생각해 보겠습니다. 탐사선은 가까워질 때 중력 때문에 빨라집니다. 하지만 다시 멀어질 때는 느려집니다. 엔진을 쓰지 않고 다른 영향을 무시하면, 충분히 먼 곳에서의 처음과 마지막 속력은 거의 같습니다. 방향은 달라져 있습니다.

**다음 장 연결**

- 같은 장면에서 관점을 바꾸어 행성도 움직이고 있음을 드러냄

**제작 메모**

- 비교 조건은 무추진·마찰 없는 단순한 중력 통과와 충분히 먼 전후 지점임
- `속력`과 `방향을 포함한 속도`를 혼동하지 않음
- 대화의 `10 → 15 → 20 → 15 → 10`은 개념 예시였음. 실제 측정값이 아니므로 화면에서는 수치 없이 표현함
- 원리 확인용 근거: [NASA의 중력 도움 설명](https://science.nasa.gov/learn/basics-of-space-flight/primer/)

### 12. 하지만 행성은 움직인다

**핵심 메시지**

- 움직이는 행성과의 중력 상호작용으로 태양 기준 속력이 달라질 수 있음

**PPT 문구**

> 하지만  
> 행성은 움직인다.

**애니메이션**

1. 태양 기준으로 보는 장면으로 전환함
2. 행성이 공전 방향으로 이동함
3. 적절한 경로로 접근한 탐사선이 휘어 나감
4. 통과 후 더 빠르게 이동하는 모습을 보여줌
5. 공전의 작은 구간을 확대해 보여주는 경우 행성의 이동은 완만한 직선으로 단순화할 수 있음

**말할 내용**

> 하지만 실제 행성은 태양 주위를 움직입니다. 태양에서 보면, 탐사선은 접근 경로에 따라 행성의 움직임을 이용해 더 빨라질 수 있습니다. 중력이 에너지를 새로 만들어 내는 것이 아니라 행성의 운동 에너지를 아주 조금 나누어 받는 것입니다.

**다음 장 연결**

- 움직이는 행성을 이용한 경로를 더 넓은 여정으로 연결함

**제작 메모**

- 11장과 관측 기준이 달라졌음을 말과 장면 전환으로 구분함
- “행성 뒤쪽이면 언제나 같은 양만큼 가속된다”는 규칙으로 단순화하지 않음
- 행성 표면에 닿거나 공처럼 반사되는 연출을 사용하지 않음
- 전문적인 에너지·운동량 수식은 화면에 넣지 않음
- 보충 근거: [ESA의 중력 도움 설명](https://www.esa.int/Enabling_Support/Operations/What_are_gravity_assists)

**제작 메모**

### 14. 아무렇게나 지나가도 될까?

**핵심 메시지**

**PPT 문구**

> 아무렇게나 지나가도 될까?

**애니메이션**

3. 진입 위치를 바꾼 두 번째 경로를 보여줌
4. 목표 쪽으로 이어지는 경로를 강조함

**말할 내용**

> 그렇다고 행성 근처를 아무렇게나 지나가면 원하는 결과를 얻는 것은 아닙니다. 어느 방향에서 접근하고 얼마나 가까이 지나는지에 따라, 나가는 경로가 달라집니다.

**다음 장 연결**

**제작 메모**

- 소행성 관측 등 다른 사건은 중력 도움 중심의 흐름에서 생략한 것임
- 임의로 그린 곡선은 `경유 순서를 보여주는 개념도`로 표기함
- 실제 궤도와 정확한 행성 위치를 재현했다고 주장하지 않음
- 매번 속력만 증가하는 것으로 표현하지 않고, 필요한 궤도로 바뀌는 모습을 보여줌

## 7. 디자인 및 제작 원칙

### 한 장에 한 메시지

- 제목 또는 질문 하나를 가장 크게 둠
- 본문은 가능하면 1~3줄로 제한함
- 대본은 화면에 옮기지 않음
- 정보가 많아지면 글자를 줄이지 말고 장면을 나눔
- `질문 → 현상 → 답`을 여러 장으로 나누어도 됨
- 전환 장은 단어 하나만으로도 충분함
- 세 가지 효과와 경유 순서는 하나의 메시지를 보여주는 제한적인 나열로 취급함

### 발표를 돕는 시각 자료

- 애니메이션은 설명할 현상을 보여주는 데 사용함
- 장면이 화려해지는 것보다 핵심이 빨리 읽히는지를 우선함
- 큰 제목, 짧은 문구, 큰 행성과 탐사선으로 구성함
- 숫자 패널·벡터 패널·슬라이더·실행 버튼을 청중 화면에 늘어놓지 않음
- 효과음과 배경음은 확정되지 않았으므로 기본 구성에 추가하지 않음

### 화면 분위기

- 대화에서 제안된 어두운 우주 배경을 기본 시안으로 삼음
- 배경의 별은 적게 배치해 글과 경로를 방해하지 않게 함
- 탐사선과 경로의 색을 장면 사이에서 유지함
- 강조색은 소수만 사용함
- 경로 비교는 색뿐 아니라 선 종류·라벨도 함께 사용함
- 구체적인 색상 코드와 글꼴은 미확정임
- 읽기 어려운 장식 글꼴과 지나치게 가는 글씨를 피함

### 화면 배치

- 16:9 화면을 기본으로 함
- 구현 기본안은 1920×1080 무대를 화면에 맞게 비율 유지 축소하는 방식임
- 장치 크기에 따라 문장과 도형의 배치를 임의로 바꾸지 않음
- 내용이 화면 밖으로 넘치거나 세로 스크롤이 필요하지 않게 함
- 제목·그림·대본의 역할을 구분함
- 출처 상세 정보는 발표자 노트나 마지막 참고자료 영역에 둠

### 장면 연결

- 01~02: 도입 경로를 어둡게 하며 질문에 집중함
- 03~06: 지구 출발 장면을 유지하며 문제와 비유를 연결함
- 07~08: 휘어진 궤적에서 방법의 이름을 드러냄
- 10~12: 같은 현상을 비교하면서 관측 기준의 변화를 명확히 함
- 16~18: 로제타의 경로를 노선도로 단순화함
- 19~20: 도입의 질문을 회수하고 핵심 단어만 남김

### 시간과 재생 리듬

- 발표 제한 시간은 아직 정해지지 않음
- 대화에서 제안된 장당 5~15초는 짧은 장면의 리듬 예시임. 전체 장에 일괄 적용하지 않음
- `WHY?`, 마지막 `FLYBY`는 짧게 머무를 수 있음
- 원리 비교와 로제타 경로는 설명에 필요한 시간을 충분히 확보함
- 개별 애니메이션 재생 길이와 슬라이드 체류 시간을 구분함
- 발표자가 다음 장으로 넘기는 것을 기본 구현안으로 삼음
- 장면 안의 움직임은 진입 시 자동 시작하고, 필요하면 잠깐 정지 후 반복함
- 반복되는 애니메이션이 다음 장으로 자동 이동시키지 않게 함

## 8. Codex 구현 시 참고사항

### 구현 전에 확인할 것

- 실제 구현할 프로젝트의 `AGENTS.md`와 기존 파일을 먼저 확인함
- 이 문서는 구상 기준임. 기존 프로젝트 구조를 바꾸라는 지시가 아님
- 이 프로젝트에서는 `docs/md/flyby_presentation_plan.md`를 현재 발표 기획의 기준으로 사용함
- 기존 애니메이션이 있으면 읽고 재사용 가능성을 판단함
- 과거 시안의 재생 길이나 물리 수치를 새 발표 전체의 확정 조건으로 가져오지 않음
- 기존 버전의 삭제·이동·덮어쓰기는 별도 작업으로 판단함
- 이 계획서는 발표 구상을 정리한 문서임. 전체 HTML 구현과 배포는 후속 작업으로 다룸

### 구현 기본안

- 단순한 HTML·CSS·JavaScript를 우선 검토함
- 텍스트·슬라이드 전환은 HTML/CSS로 처리함
- 궤적과 탐사선 이동은 SVG 또는 Canvas 중 기존 구조에 맞는 방식을 사용함
- CSS 애니메이션은 제목과 문구의 등장에 사용함
- 그림으로 충분한 장면에 무거운 3D 라이브러리를 추가하지 않음
- 새로운 라이브러리가 필요하면 이유와 범위를 먼저 설명함
- 이 문서의 화면 문구와 발표자 노트를 분리해 관리함
- 인터넷이 없는 발표 환경에서도 글꼴·이미지·스크립트가 빠지지 않게 구성함

### 슬라이드와 장면 관리

- 슬라이드마다 고정된 번호와 역할을 부여함
- `핵심 메시지`, `화면 문구`, `애니메이션`, `발표자 노트`를 연결함
- 진입 시 해당 장면만 시작함
- 이탈 시 이전 장면의 타이머와 애니메이션을 정리함
- 이전 장으로 돌아왔을 때 장면을 일관되게 다시 볼 수 있게 함
- 로제타 경로는 사건 순서 데이터로 관리해 연도와 행성의 대응 오류를 줄임
- 청중용 화면에 구현 메모·디버그 수치·내부 파일명을 노출하지 않음

### 발표 조작

- 기본 조작안: 방향키 또는 Space로 다음 단계·다음 장 이동

- 장면 안 단계 공개와 슬라이드 이동이 충돌하지 않게 함
- 화면을 덮는 큰 탐색 버튼이나 재생 버튼은 기본으로 두지 않음
- 최종 장에서는 종료 상태를 유지함
- 발표 조작은 청중에게 설명해야 하는 실습 기능처럼 만들지 않음

### 애니메이션 정확성

- 물리 계산을 하는 장면과 설명용 궤적 장면을 구분함
- 설명용 곡선에 실제 임무 데이터라는 이름을 붙이지 않음
- 고정된 경로에서 전 구간을 같은 속도로 움직여 가속·감속 설명과 모순되지 않게 함
- 장식용 easing으로 속력이 변해 보이는 것과 개념상 속력 변화를 구분함
- 비교 장면에서는 시간 축척·관측 기준·표시 의미를 통일함
- 행성 공전 방향이 중요할 때만 간단한 화살표를 사용함
- 물리 설명용 벡터 패널은 만들지 않음
- 화면 크기가 달라져도 행성·탐사선·궤적이 따로 움직이거나 잘리지 않게 함
- 모션 감소 설정에서는 핵심 정지 장면과 단계별 상태를 보여줄 수 있게 함

### 코드 및 파일 작업 원칙

- 기존 프로젝트의 언어·주석·폴더 규칙을 따름
- 함수와 중요한 튜닝값의 의미를 한국어 주석으로 남김
- 승인받은 구현 범위의 파일만 변경함
- `sources/`와 같은 동기화 참고 파일은 수정하지 않음
- 빌드나 정적 검사 결과와 실제 화면 확인 결과를 구분함
- 실행하지 않은 검사나 보지 않은 화면을 확인했다고 기록하지 않음

| 합칠 장면 | 합칠 수 있는 조건 |

- 로제타 경로가 복잡해지면 추가 장면으로 나눌 수 있음
- 최종 장수는 리허설 후 결정함
